# The web interface

Loaded when you touch the files above (path-scoped rule). The root CLAUDE.md has the rules that always apply.

- **Interface hs-ui: REMOVED 2026-10-22** (the web interface replaced it; its history stays in docs/Entwicklungsnotizen.md#interface-hs-ui). `hs` without arguments shows `hs help`; the Rust package pkgs/hs-pool, `hsPool` in configuration.nix, the `tab:` flags of the registry and the CI job `interface` are gone. What stays: the `hs sys ...` rows (kind `sys` in scripts/lib/registry.tsv) are the contract the web interface reads and changes through, and their machine-readable `list`/`--dry-run` lines must not change (tests/pool-look.sh compares plans byte for byte). A terminal shell into the server is `ssh` + `hs`, or the opt-in browser terminal (`webTerminal`).

- **Web interface** (docs/PLAN-web-backend.md). Fast loads: reads are stale-while-revalidate (an answer up to 30 min old is shown at once while a new one is read, X-HS-Age says how old); the warm-up thread keeps EVERY read without arguments and everything somebody asked for (also with its arguments) fresh while a session was seen in the last 5 min; the cache is saved to /run/hs-web/cache.json and loaded at start, so a restart is not cold; the browser prefetches a page's reads when the pointer reaches its tree entry (web/src/readsfor.js, tests/web-cache.sh); the slow reads (scripts/lib/collected-reads.tsv) are kept in the state database table `reads` by the collector scripts/reads-collect.sh (timer hs-reads-collect every 15 s, only with webUi; `hs sys state reads` shows age and milliseconds) and served from there while the output is at most 3 min old, otherwise the web interface runs the script itself as before; the top bar shows how old the page's data is (X-HS-Age, web/src/shell/Fresh.svelte) with a refresh button (`?fresh=1` runs the scripts now) and the page Data (/operations/data, `hs sys reads status`) lists every kept read with interval, age and duration; sessions survive restarts via hashes in /run/hs-web. Browser UI, off unless `webUi = true` (machine.toml; `webPort`, `webAccent` = main colour as #rrggbb, default purple #9184d9). ONE Python process on the host (scripts/web-serve.py, hs-web.service, root, never in Incus, never a Zoraxy rule, plain HTTP on LAN/Tailscale) hands out the Svelte frontend (web/, pkgs/hs-web.nix) and wraps `hs sys ...` (reads) and `plan`/`start` (changes); the state database stays history only. Only Domain Admins and the local adminuser sign in (adminuser alone while storage is locked); passwords go on stdin, every POST needs Origin + CSRF token. **Look (redesign phase 1; spec web/design/HANDOFF.md):** tokens in web/src/tokens.css (`--bg --panel* --line* --fg* --accent --accent-ink --h1..--h4 --ok/--warn/--bad/--info/--off`, `--r` 0 = hard edges, dark and light by system or the top-bar toggle, `theme.svelte.js`), global classes in web/src/base.css; the accent still comes from `/theme.css` (`--color-accent`), accent-ink and `--h1..--h4` are DERIVED from it in CSS, never hard-coded; the old `--color-*`/`--st-*` names are aliases of the new tokens. Fonts Geist + Geist Mono are self-hosted in web/src/fonts (OFL.txt next to them, no CDN). Shared components: web/src/ui (StatusDot, Chip, Banner, EmptyState, Skeleton, Switch, Combobox, Drawer, Kv, Split) plus shell/ (Table, UsageBar, Spark, PlanDialog, PageHeader, PageState, PageFrame, Halftone); a page uses these, never a hand-drawn dot, bar, banner or select. Every address is /node/<name>/<inner path> (the local node too; `route.path` is the INNER path, `go('/x')` means this node's page, redirects in web/src/redirects.js via routes.js). The halftone background is shell/Halftone.svelte (canvas, Bayer dithering); never inside a button. Accent tokens come from `/theme.css`. The proxyserver rows include a Ports page (`/proxy/ports`, `ports` key of the VPS status document, alias `/proxy/game-ports`). Built so far: sign-in page, backend auth, theme, generic read API (`READS` allowlist in web-serve.py: add a read there AND it must be a `sys` row), app shell, Summary page; all pages except the proxyserver ones, plus plan/start for a closed list of changes (`CHANGES` allowlist in web-serve.py, kept in step with `scripts/lib/config-keys.sh` for settings); create dialog for forms (web/src/shell/CreateDialog.svelte, `CHANGES` entries may be dicts with options and `stdin` for passwords/passphrases, which never go through argv or logs), `POST /api/unlock`, opt-in browser terminal (`webTerminal`: websocket + pty in scripts/web_terminal.py, shell as adminuser in a transient systemd unit, never inside hs-web: NoNewPrivileges would break sudo; the shell is a tmux session per web user and target on its own tmux server in the unit hs-web-tmux, so close/popout/reconnect reattach to the same shell and only `exit` ends it); tables: a list is the shared `web/src/shell/Table.svelte` (declared columns, click a header to sort ascending / descending / back; the logic is web/src/shell/sort.js, tests/web-sort.sh), every `.table` header sticks to the top of the scrolling area (base.css; `--sticky-top` is the padding of the area); a new list page uses `Table`, not a hand-written `<table>`; disk and pool usage in a list is `web/src/shell/UsageBar.svelte` (fixed-width bar + "used / size", amber over 90 %), never a hand-made bar; tests: tests/web-*.sh (web-login, web-forms-*, web-unlock, web-sys-lists, web-data-settings, web-disk-change, ...). The proxyserver pages and the VPS buttons belong to the capability `vps` (on when the runtime setting `vpsHost` or `proxyStatusUrl` is set; details, the forced-command key and its rules: capabilities/vps/NOTES.md). Never give the VPS key a shell or more words than `update|watch`.

- No web UI for ZFS any more: Cockpit and then WebZFS were removed (WebZFS could not schedule anything on
  NixOS, and `hs` covers what it showed: pools `hs pool`, datasets `hs manage-shares`, SMART `hs disk health`,
  snapshots `hs share <share> snapshot|snapshots|rollback` (share-snap.sh, ZFS layout only), scrub is
  `services.zfs.autoScrub`). Don't bring one back. If /var/lib/webzfs or the user `webzfs` still exist on a
  server, `hs cleanup` says so.
